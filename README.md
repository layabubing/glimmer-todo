# Glimmer Todo · 浮光待办

Windows 桌面悬浮待办、日程与番茄钟工具，使用 C++20 和 Windows 原生界面。支持 Windows 10 1703 及以上版本、Windows 11，要求 x64 系统。

## 下载

从本仓库的 Releases 页面下载 `GlimmerTodo-v1.3.0-windows-x64.zip`，解压后双击 `GlimmerTodo.exe` 运行。

默认窗口为 260 × 300，最小可调整至 240 × 200；尺寸使用 Windows 逻辑像素。界面包含紧凑标题、分段导航、圆角待办卡片和新增输入框。标题旁的主题色圆点表示自动隐藏已开启。

通过窗口内的“待办 / 日程 / 专注”按钮切换功能，也可以聚焦导航后使用左右方向键。切换页面时，导航指示条滑动，页面内容轻微移入，动画持续约 180 毫秒；系统关闭界面动画时，程序同步关闭切换动画。专注页面需要至少 320 的窗口高度。

## 外观主题

点击右上角“主题”，或进入设置中的“外观主题”，选择“晨光 · 浅色”“夜色 · 深色”或“森林 · 绿色”。主题会立即应用到主窗口、设置和日程编辑器，并自动保存。按钮提供悬停和按压反馈，专注页面集中显示倒计时、进度和今日完成次数。

## 日程

- 在“日程”页面点击“新增日程”，填写内容、本地日期与时间，可选择每天或每周重复。
- 日程按时间排序；双击文字或按 F2 编辑，点击左侧方框完成，点击右侧删除按钮或按 Delete 删除。
- 重复日程完成后推进到下一个未来日期，保留本地时刻；一次性日程可以完成或恢复。
- 到时通过系统托盘提醒。游戏或指定软件处于前台时延后提醒，切换离开后按顺序显示。
- 应用需要保持运行；退出后错过的未提醒日程在下次启动时提醒。Windows 通知设置可能影响提醒的展示与声音。

## 番茄钟

“专注”页面默认专注 25 分钟、短休息 5 分钟、每完成四次专注进入 15 分钟长休息。每个阶段结束后提醒，并等待点击“开始”进入下一阶段。

支持开始、暂停、继续、重置和跳过。重置从新一轮专注开始；跳过阶段不增加完成次数。今日完成次数按本地日期统计。

暂停后可调整时长：专注 1–180 分钟、短休息 1–60 分钟、长休息 1–120 分钟，点击“保存时长”应用。运行中的截止时间自动保存，休眠或重启后继续按实际经过的时间计算；错过截止时间时完成当前阶段，下一阶段等待手动开始。

## 更新

打开“设置”，点击“检查更新”。发现更新后点击“下载更新”，下载完成并通过 SHA256 校验后，点击“安装并重启”并确认。程序从 `layabubing/glimmer-todo` 的最新正式 GitHub Release 获取 `GlimmerTodo.exe` 附件及其摘要。

检查和下载在后台执行。更新助手等待旧进程退出后替换程序并启动新版本；数据保留在原本的本地目录。程序目录需要具备写入权限，更新前的 EXE 保存在同目录的 `.previous` 文件中。`.glimmer-update` 目录存放更新助手与下载文件。

## 使用

- 在底部输入待办，按 Enter 或点击加号保存。每条待办最多 500 个 UTF-16 字符。
- 点击左侧方框完成或恢复待办。双击待办文字或选中后按 F2 编辑；编辑时按 Esc 取消。
- 点击右侧删除按钮或选中后按 Delete 删除待办。右键菜单可以清理全部已完成待办。
- 拖动窗口顶部移动位置，拖动边缘调整大小。位置、尺寸和置顶选项自动保存。
- 点击“设置”，管理自动隐藏和置顶选项，勾选需要检测的软件。
- 在设置中输入进程文件名，例如 `notepad.exe`，点击“添加软件”；也可以通过“选择 EXE…”选择软件实际运行的主程序。
- 点击“收起”或关闭窗口可收起到系统托盘。双击托盘图标，或者再次运行 EXE，可以显示已有窗口。右键托盘图标可以退出。
- Ctrl+N 聚焦新增待办输入框。列表支持方向键、Space 完成切换、Enter 编辑和 Tab 切换控件。

自动隐藏按当前前台窗口所属的 EXE 文件名匹配，忽略英文大小写。已添加的软件进入前台时，待办、设置和程序选择窗口隐藏；软件进入后台、最小化或退出后恢复显示。恢复显示使用不激活窗口的方式，保留当前程序的键盘焦点。手动收起后保持收起状态，直到主动显示。

切换 Windows 虚拟桌面后，待办及已打开的设置窗口会跟随当前桌面。各个桌面共用待办和软件规则，自动隐藏根据当前桌面的前台程序生效。程序保留输入框内容、窗口位置与手动收起状态。

选择软件时，请选择实际运行程序；使用独立启动器的软件，需要添加运行后的程序文件名。相同文件名的软件共用检测规则。

## 本地数据

待办、日程、番茄钟和设置保存到 `%LOCALAPPDATA%\DesktopList\state.json`。每次修改立即写入文件，刷新到磁盘后原子替换正式文件。可以在退出应用后复制该文件备份。检查和下载更新需要联网。

前台检测使用 Windows 前台切换与窗口隐藏事件通知，每 250 毫秒检查一次当前状态。程序保持单个实例运行。

## 编译与测试

本项目附带 nlohmann/json 3.12.0 的单文件依赖与 MIT 许可。编译环境使用 w64devkit 2.11.0；安装脚本从官方发布地址下载，并检查 SHA256。环境保存在项目的 `.tools` 目录。

在项目目录的 PowerShell 中执行：

```powershell
.\setup.ps1
.\build.ps1
```

生成文件为 `build\GlimmerTodo.exe`。可以通过 `./build.ps1 -Test` 运行数据逻辑检查，再通过 `./package.ps1` 生成 `dist` 中的程序和发布压缩包。运行程序后执行下列命令，可以采样实际进程的内存、CPU 时间和句柄数量：

```powershell
.\tests\measure.ps1 -DurationSeconds 60
```

采样报告保存在 `.work\memory.json`。指标使用 MB，即 1,000,000 字节。采样期间工作集超过 50 MB 时，脚本报告测试失败。程序通过原生界面和较少的常驻对象控制内存占用。
